# JOSEON OUTLAW — 향후 작업 계획

> 상태: 아이디어 검토 및 기술 설계 단계
>
> 목표: 6명·7주 안에 Windows에서 8~10분간 완주 가능한 조선풍 오픈존 3D 액션 어드벤처 데모 제작
>
> 원칙: 게임은 AI 없이도 완주 가능해야 하며, AI는 대사 표현만 담당하고 게임 상태를 직접 변경하지 않는다.

## 1. 프로젝트 정의

`JOSEON OUTLAW`는 조선 후기에서 영감을 받은 가상 마을을 배경으로 한다. 플레이어는 떠돌이 검객이 되어 주민에게 의뢰를 받고, 산길의 도적을 물리친 뒤 물건을 회수해 돌아온다.

이번 프로젝트에서 말하는 오픈월드는 대규모 심리스 월드가 아니라, 마을과 산길을 자유롭게 이동할 수 있는 **소규모 오픈존**이다.

### 성공 기준

- Windows 실행 빌드를 별도 설정 없이 시연할 수 있다.
- 시작부터 보상 수령까지 8~10분 안에 완주할 수 있다.
- 이동, 카메라, 상호작용, 전투, 퀘스트가 하나의 흐름으로 연결된다.
- NPC 대사가 성격과 퀘스트 상태를 반영한다.
- AI 서버가 중단되거나 응답에 실패해도 고정 대사로 진행할 수 있다.
- 사용한 코드, 모델, 음성, 3D 에셋의 출처와 라이선스를 추적할 수 있다.
- 게임과 AI의 성능 및 품질을 동일한 테스트 시나리오로 반복 측정할 수 있다.

## 2. 최종 시연 흐름

1. 플레이어가 마을에 도착한다.
2. 주민 또는 상인 NPC와 대화한다.
3. 도적에게 빼앗긴 장부 회수 의뢰를 수락한다.
4. 산길로 이동한다.
5. 도적 2명과 검으로 전투한다.
6. 장부를 획득한다.
7. 마을로 돌아간다.
8. NPC가 완료된 퀘스트 상태를 반영한 대사를 말한다.
9. 보상을 받고 데모가 끝난다.

AI 대화는 퀘스트 시작과 완료 지점에 집중한다. 자유 대화가 게임의 핵심 진행을 막지 않게 한다.

## 4. 잠정 기술 구성

기술은 문서만으로 확정하지 않고 1주차 기술 스파이크 결과로 고정한다.

### 게임 클라이언트

- Godot 4 안정 버전
- GDScript
- `CharacterBody3D`
- `AnimationTree`
- `NavigationAgent3D`
- Godot Resource 기반 NPC·퀘스트·전투 데이터
- Git LFS를 통한 대용량 바이너리 에셋 관리

### AI 서버

- Python + FastAPI
- 우선 HTTP JSON 사용
- Ollama와 llama.cpp를 비교한 뒤 하나만 채택
- 기준 PC에서 한국어 품질과 응답 시간을 만족하는 양자화 모델 선택
- 데이터베이스 없이 메모리와 JSONL 로그로 시작

### TTS

- 한국어를 지원하는 MeloTTS 우선 검증
- 자막을 먼저 표시하고 음성은 비동기로 재생
- 모델, 음성 가중치, 학습 데이터 관련 라이선스를 코드 라이선스와 별도로 확인
- 품질 또는 지연 기준을 통과하지 못하면 P2에서 제외

## 5. 시스템 책임과 데이터 흐름

```text
Godot Game Client
 ├─ GameState
 ├─ QuestManager
 ├─ Player / Camera
 ├─ Combat
 ├─ NPC FSM
 ├─ Interaction
 ├─ DialogueManager
 ├─ AIClient
 └─ Metrics
        │ HTTP JSON
        ▼
FastAPI Process
 ├─ PromptBuilder
 ├─ LLMAdapter
 ├─ ResponseValidator
 ├─ TTSAdapter (P2)
 └─ MetricsLogger
```

### 게임 클라이언트가 결정하는 것

- 퀘스트 수락과 완료
- 아이템 획득과 보상
- 적대 상태
- 체력과 전투 결과
- 다음 목표와 시연 진행

### AI가 생성할 수 있는 것

- NPC 대사
- 감정 태그
- 제한된 대화 의도
- 성격과 세계관에 맞는 표현

LLM 응답만으로 퀘스트나 전투 상태가 변경되어서는 안 된다.

### 최소 AI 응답 형식

```json
{
  "text": "북쪽 산길에서 도적을 보았소.",
  "emotion": "worried",
  "intent": "give_hint"
}
```

허용된 `intent`만 처리한다. JSON 파싱 실패, 허용되지 않은 값, 타임아웃은 고정 대사로 대체한다.

## 6. 6명 역할 분배

| 역할 | 주 책임 | 보조 책임 |
| --- | --- | --- |
| 테크 리드·통합 | 구조, 빌드, 공통 인터페이스, 코드 리뷰 | 성능 기준, 릴리스 |
| 플레이어·카메라 | 이동, 카메라, AnimationTree | 상호작용 |
| 전투·적 AI | 공격, 피격, 체력, Navigation, FSM | 전투 연출 |
| 월드·테크 아트 | 마을, 에셋 파이프라인, 조명, 충돌체 | UI와 최적화 |
| AI 백엔드·TTS | FastAPI, LLM, 응답 검증, TTS | AI 성능 측정 |
| 퀘스트·대화·UI | QuestManager, DialogueManager, 자막, HUD | 테스트 시나리오 |

작업자는 기능별로 분리하되 게임플레이, 콘텐츠, AI의 2인 그룹으로 상호 리뷰한다. 씬 파일은 소유자를 지정해 동시 편집 충돌을 줄인다.

## 8. 성능·품질 측정

### 기준 환경

다음 항목을 먼저 고정해야 수치가 의미를 가진다.

- CPU, GPU, RAM, VRAM
- Windows 버전
- 해상도와 그래픽 옵션
- 로컬 LLM 모델과 양자화 방식
- AI 비실행, LLM 추론 중, TTS 생성 중 상태

### 게임 지표

- 평균 FPS
- 1% Low FPS 또는 p95/p99 프레임 타임
- 실제 시나리오 NPC 4명 성능
- NPC 10명 부하 시나리오
- RAM 및 VRAM 사용량
- 최초 실행과 씬 로딩 시간
- 10회 연속 완주 성공률

### AI 지표

- 첫 토큰 시간 p50/p95
- 전체 응답 시간 p50/p95
- JSON 파싱 성공률
- 퀘스트 상태 반영 정확도
- 세계관 위반률
- NPC 성격 유지율
- fallback 성공률
- 모델별 RAM·VRAM 사용량
- TTS 생성 시간 p50/p95

평가 데이터는 `NPC 2명 × 퀘스트 상태 4개 × 질문 5개 = 40개`를 기본 세트로 사용한다. 세계관 위반과 성격 유지 여부는 두 명이 독립 평가하고 불일치를 재검토한다.

## 10. 1주차 Go/No-Go 게이트

### 반드시 통과해야 하는 항목

- [ ] Windows 빌드 성공
- [ ] 캐릭터·이동·카메라 동작
- [ ] 최종 스켈레톤과 공격 애니메이션 사용 가능
- [ ] Godot–FastAPI 통신 성공
- [ ] 로컬 LLM 한국어 응답 성공
- [ ] 합법적으로 사용할 환경 에셋 확보

필수 항목 하나라도 실패하면 해당 기술 또는 콘텐츠 전략을 재검토한다.

### 실패 시 범위 축소 규칙

- TTS 품질 또는 지연 실패 → TTS 제외
- LLM 품질 실패 → 자유 입력을 줄이고 선택지 기반 대화로 제한
- 게임과 LLM의 GPU 경쟁 → 더 작은 모델, CPU 추론 또는 추론 중 그래픽 부하 축소
- FPS 기준 실패 → NPC 수와 환경 밀도 감소
- 전투 애니메이션 실패 → 공격 1종과 피격 1종으로 축소
- 조선 에셋 부족 → 세미 스타일라이즈드 조선풍 가상 세계로 시각 방향 통일
