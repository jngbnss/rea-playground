# 10. Ollama·llama.cpp와 LLM 후보 벤치마크 계획

> 상태: 계획 + 도구 완성, qwen3:8b 실측 2회 완료. 8B 실시간 방식은 불합격으로 제외한다.
> 도구: [`tools/llm_bench.py`](../tools/llm_bench.py), 평가 세트: [`data/eval_dialogue.jsonl`](../data/eval_dialogue.jsonl) (생성기 [`tools/make_eval_set.py`](../tools/make_eval_set.py))
> 검사: `tests/test_llm_bench.py` (모의 서버에 실패를 일부러 섞어 지표가 정확히 집계되는지 확인)

## 1. 무엇을 결정하나

1. **런타임:** Ollama와 llama.cpp server 중 하나
2. **모델:** 기준 PC에서 한국어 품질과 응답 시간을 만족하는 양자화 모델 하나
3. **동시 실행 가능 여부:** 게임과 LLM이 같은 GPU에서 돌아갈 때 FPS 목표를 지키는지

## 2. 합격 기준 (1주차 Go/No-Go)

| 지표 | 기준 | 이유 |
|---|---|---|
| 첫 토큰 p95 | **1.5초 이하** | 자유 입력을 켤 때만 적용. 상태별 첫 대사는 캐시에서 즉시 표시 |
| 전체 응답 p95 | **3.0초 이하** | 대사 한두 문장. 넘으면 고정 대사가 먼저 나간다 |
| JSON 파싱 성공률 | 95% 이상 | JSON 모드에서 이보다 낮으면 모델이나 프롬프트를 바꾼다 |
| 정책 통과율 (스키마, intent, 금칙어) | 85% 이상 | 실패분은 고정 대사로 나가므로 게임은 멈추지 않는다. 다만 너무 낮으면 AI의 의미가 없다 |
| 상태 반영률 (자동 1차) | 80% 이상 | 키워드 기반 1차 판정. 최종은 사람 평가 |
| 세계관 위반률 | 2% 이하 | 금칙어 기반 |
| 보상 거짓말 (state_lie) | 0건 | 보상 전 상태에서 보상을 준 것처럼 말하면 안 된다 |
| VRAM | 게임 + 모델이 GPU 메모리의 85% 이하 | 넘으면 더 작은 모델 또는 CPU 추론 |

기준을 넘지 못하면 계획서 10절의 축소 규칙을 따른다: 자유 입력을 줄이고 선택지 기반 대화로 제한, 더 작은 모델, CPU 추론.

## 3. 후보

| 구분 | 후보 | 비고 |
|---|---|---|
| 런타임 | **Ollama** | 설치가 쉽고 모델 관리가 편하다. OpenAI 호환 `/v1/chat/completions`, `response_format: json_object` 지원 |
| 런타임 | **llama.cpp server** | 더 가볍고 설정을 세밀하게 할 수 있다. JSON 스키마 문법 제약(GBNF) 지원 |
| 모델 | 7~9B급 다국어 instruct 모델 Q4_K_M 양자화 | 1주차에 그때 최신 한국어 성능 상위 모델 3개를 골라 같은 조건으로 잰다 |
| 모델 | 3~4B급 | 게임과 GPU를 나눠 써야 할 때의 대안 |

모델 목록은 이 문서에 고정하지 않는다. 출시 주기가 빨라서 1주차에 다시 고른다. **같은 평가 세트, 같은 프롬프트, 같은 PC**만 지키면 된다.

## 4. 측정 절차

```bash
# 0. 파이프라인 점검 (모델 불필요)
python -m tools.llm_bench --mock

# 1. 모델별 측정: 케이스당 3회, 결과 원본 보존
python -m tools.llm_bench --base-url http://127.0.0.1:11434/v1 --model <모델> --runs 3 --out metrics/raw/<모델>.jsonl
python -m tools.llm_bench --base-url http://127.0.0.1:8080/v1  --model local  --runs 3 --out metrics/raw/<모델>-llamacpp.jsonl

# 사고형 모델(Qwen3 등)은 --no-think 로 사고 과정을 끈다 (Ollama에서 reasoning_effort="none")
```

조건 세 가지를 각각 잰다.

1. **AI 단독:** 게임을 끈 상태
2. **게임 + AI:** 마을 장면에서 게임을 실행한 채로 측정. 게임 쪽 FPS·프레임 타임은 Godot `Metrics` autoload가 같은 시간대에 기록한다
3. **콜드 스타트:** 모델을 내린 뒤 첫 요청. 시연 직전 모델을 미리 올려 두는 절차가 필요한지 판단한다

평가 세트는 **NPC 2명 × 퀘스트 상태 4개 × 질문 5개 = 40개**다. 질문 5개는 모든 상태에서 같다: 먼저 말 걸기, 목표 질문, 마을 질문, 시대에 맞지 않는 질문(휴대폰·인터넷), 보상 거짓말 시도.

자동 지표 다음에는 **두 명이 40개 응답을 독립적으로 평가**한다(성격 유지, 세계관, 자연스러움, 각 1~5점). 불일치가 2점 이상인 항목은 함께 다시 본다.

## 5. 실제 측정 기록

### 2026-10-15: qwen3:8b (Ollama, 사고 끔, JSON 모드), 이 저장소 작업 PC

- GPU: NVIDIA GeForce RTX 4060 8GB. 측정 중 같은 PC에서 다른 프로세스가 돌고 있었으므로 **시연 PC 기준값이 아니다.** 게임은 실행하지 않았다(조건 1, AI 단독).
- 원본: [`evidence/bench-qwen3-8b.jsonl`](evidence/bench-qwen3-8b.jsonl)(1차), [`evidence/bench-qwen3-8b-run2.jsonl`](evidence/bench-qwen3-8b-run2.jsonl)(2차). 요약은 같은 폴더의 `*-summary.json`
- 1차 수치는 1차 이후 보강한 검증기로 다시 채점한 값이다(`--rescore`).

| 지표 | 기준 | 1차 | 2차 (프롬프트 보강) | 판정 |
|---|---|---|---|---|
| 첫 토큰 p50 / p95 | p95 ≤ 1.5초 | 3.6 / 9.7초 | 6.9 / 12.5초 | **불합격** |
| 전체 응답 p50 / p95 | p95 ≤ 3.0초 | 5.3 / 11.2초 | 8.6 / 14.2초 | **불합격** |
| JSON 파싱 | ≥ 95% | 100% | 100% | 합격 |
| 정책 통과 | ≥ 85% | 77.5% | **92.5%** | 2차 합격 |
| 상태 반영 (자동) | ≥ 80% | 81.2% | 66.7% | 2차 불합격 |
| 세계관 위반 | ≤ 2% | 17.5% | **2.5%** | 경계 |
| 보상 거짓말 | 0건 | 0건 | 0건 | 합격 |
| VRAM 최대 | 게임 포함 85% 이하 | 6.4GB / 8GB | 6.5GB / 8GB | **불합격** (게임에 남는 메모리가 약 1.5GB) |
| 콜드 스타트 | – | – | 55.9초 | 시연 전 워밍업 필수 |

**1차에서 발견해 고친 것**

- **세계관 위반 17.5% 중 7건이 모두 "휴대폰·인터넷" 질문**이었다. 모델이 플레이어가 한 말을 그대로 따라 했고("휴대폰은 손에 드는 작은 물건이오"), 금칙어 검사에 걸려 고정 대사로 대체되었다. 프롬프트에 "모르는 낱말은 따라 말하지 말고 모르겠다고만 한다"를 추가하자 2차에서 1건으로 줄었다("모르겠소. 무슨 소리인지 모르겠소.").
- **검증기가 놓친 실패 2종**을 추가로 막았다. 영어 섞임("장부가 드 arrived하오?", 2차에서도 "봉 combustion") 그리고 낱말 반복 붕괴("놈들 놈들 놈들 놈들")다. 이제 둘 다 고정 대사로 대체된다.
- 보상 거짓말 판정 문구 중 "쉰 냥이오"는 "끝나면 주리라" 같은 정상 문장까지 잡아서, "약속한 쉰 냥"으로 좁혔다.
- 2차 첫 시도는 40건 모두 무응답이었다. 모델이 메모리에서 내려가 있었고 다시 올리는 데 약 55초가 걸리는데, 요청마다 20초 타임아웃으로 끊겼기 때문이다. 벤치마크에 **워밍업 단계**를 넣어 해결했다. 게임 입장에서는 이 경우에도 고정 대사가 100% 나가 진행이 막히지 않았다.

**사람이 봐야 하는 오류 (자동 지표 통과분)**

- 상태 착오: 퀘스트가 끝났는데 주모가 "서낭당 쪽에서 불을 피우구먼. 조심해라"라고 한다.
- 사실 지어내기: "무너진 창고 속에 두 놈 죽은 체 놓여 있었나오", "봉수대 쪽".
- 말투 이탈: 하오체여야 할 윤 행수가 "먼저 도적을 찾아라"처럼 해라체를 쓴다.

### 2026-10-15: qwen3:4b-instruct (Ollama, 사고 끔, JSON 모드)

- 환경: 이 저장소 작업 PC, RTX 4050 Laptop GPU 6GB, AI 단독, 40문항 1회
- 원본: [`evidence/bench-qwen3-4b.jsonl`](evidence/bench-qwen3-4b.jsonl), 요약: [`evidence/bench-qwen3-4b-summary.json`](evidence/bench-qwen3-4b-summary.json)

| 지표 | 기준 | 실측 | 판정 |
|---|---|---|---|
| 첫 토큰 p95 | ≤ 1.5초 | 0.381초 | 합격 |
| 전체 응답 p95 | ≤ 3.0초 | 2.115초 | 합격 |
| JSON 파싱 | ≥ 95% | 100% | 합격 |
| 정책 통과 | ≥ 85% | 80.0% | 불합격 |
| 상태 반영 | ≥ 80% | 68.8% | 불합격 |
| 세계관 위반 | ≤ 2% | 20.0% | 불합격 |
| 보상 거짓말 | 0건 | 0건 | 합격 |
| VRAM 최대 | 게임 포함 85% 이하 | 5,884MiB / 6GB | 불합격 |
| 콜드 스타트 | — | 43.9초 | 시연 전 워밍업 필요 |

**판정:** 지연은 개선됐지만 정책·상태·세계관·VRAM 기준을 넘었다. 자유 입력은 끄고, 상태별 백그라운드 캐시와 검증된 대사만 사용한다. 캐시 미완성·서버 중단·2초 초과는 즉시 고정 대사로 전환한다.

**결론과 확정 설계**

1. **이 PC에서 8B 모델을 대화 중에 실시간으로 쓰지 않는다.** 지연과 VRAM 기준을 모두 넘었고 게임까지 같이 돌리면 더 나빠진다.
2. 퀘스트 진행은 항상 고정 선택지와 게임 이벤트가 담당한다. `quest_state_changed`가 발생하면 두 NPC의 다음 대사 후보를 백그라운드에서 생성해 상태별 캐시에 저장한다.
3. 플레이어가 NPC에게 접근하면 캐시를 읽고, 준비되지 않았으면 고정 대사를 즉시 표시한다. 자유 입력은 선택 기능이며 **2초 안에 검증된 응답이 없으면 폐기**한다.
4. 1주차에는 3~4B 모델 하나를 Ollama와 llama.cpp에서 같은 40문항으로 비교한다. AI 단독 기준을 통과한 조합만 게임 동시 실행을 측정한다.
5. 3~4B도 전체 응답 p95 3초 또는 게임 포함 VRAM 85% 기준을 넘으면 이번 데모의 자유 입력을 끄고, 캐시된 생성 대사와 고정 선택지만 사용한다.
6. 상태별로 말하면 안 되는 사실을 정책 데이터에 추가해 완료 후 도적 위협처럼 자동 지표를 통과한 상태 착오도 차단한다.

## 6. 알려진 함정

- **사고형 모델은 사고 과정이 전체 시간을 잡아먹는다.** 끄지 않으면 첫 요청에서 60토큰을 생성하는 데 76초가 걸렸고, 그 동안 `content`는 비어 있었다. Ollama OpenAI 호환 API에서는 `reasoning_effort: "none"`으로 꺼진다. `think: false`와 프롬프트의 `/no_think`는 이 경로에서 효과가 없었다.
- **콜드 스타트.** 모델이 메모리에 없으면 첫 요청에 수십 초가 걸린다. 시연 전에 더미 요청으로 모델을 올려 두고, Ollama `keep_alive`를 길게 잡는다.
- **Windows 콘솔 인코딩.** Git Bash의 curl로 한글 JSON을 보내면 깨질 수 있다. 측정은 반드시 이 도구(UTF-8 고정)로 한다.
