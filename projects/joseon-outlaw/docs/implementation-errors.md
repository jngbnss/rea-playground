# JOSEON OUTLAW 구현 오류 기록

각 페이즈 시작 전에 이 파일을 확인하고, 실제로 발생한 오류만 기록한다.

## 페이즈 1 — 환경·기술 검증

### P1-E001 · Godot 실행 파일이 PATH에 없음

- 발생 단계: 환경 확인
- 증상: `where godot`, `where godot4` 모두 결과 없음
- 원인: Godot가 시스템에 설치되지 않음
- 복구: 공식 `godotengine/godot-builds` 4.7.2-stable Windows 표준 빌드를 `.tmp/godot/`에 내려받아 프로젝트 도구가 명시적으로 사용하게 한다.
- 상태: 해결

### P1-E002 · Git Bash에서 상대 경로의 GUI Godot 실행 실패

- 발생 단계: 스모크 실행
- 증상: `../../.tmp/godot/Godot_v4.7.2-stable_win64.exe --version`이 `command not found`로 종료
- 원인: 콘솔 출력이 필요한 자동화에서 GUI 서브시스템 실행 파일을 상대 경로로 직접 호출함
- 복구: 자동화 기본값을 절대 경로로 해석되는 `Godot_v4.7.2-stable_win64_console.exe`로 변경했다.
- 상태: 해결

### P1-E003 · Windows 내보내기 도구의 기본 출력 경로 누락

- 발생 단계: 빌드
- 증상: `python -m tools.export_windows`가 `NameError: DEFAULT_OUTPUT is not defined`로 종료
- 원인: Godot 콘솔 실행 파일명 수정 중 인접한 `DEFAULT_OUTPUT` 선언을 잘못 교체함
- 복구: `DEFAULT_BIN`과 `DEFAULT_OUTPUT`을 별도 상수로 복원하고 실제 내보내기·실행까지 재검증했다.
- 상태: 해결

## 페이즈 2 — 플레이어 수직 슬라이스

### P2-E001 · GDScript 파싱 실패로 스모크가 종료되지 않음

- 발생 단계: 구현 / 스모크
- 증상: 헤드리스 스모크가 60초 타임아웃됐고, verbose 에디터 실행에서 `PackedStringArray.any()` 없음과 동적 노드 속성 타입 추론 오류가 출력됨
- 원인: Godot 4.7의 `PackedStringArray`에 `any()`가 없고, `Node`로 추론된 값에서 `global_position` 타입을 추론하려 함
- 복구: 명령행 인자를 명시적 반복문으로 검사하고, 플레이어를 `CharacterBody3D`로 캐스팅한 뒤 사용자 메서드는 `call()`로 호출했다. 이후 이동 4.13m·점프 속도 5.67m/s를 실제 물리 프레임에서 확인했다.
- 상태: 해결

### P2-E002 · 실패 로그 함수 선언을 잘못 덮어씀

- 발생 단계: 오류 진단
- 증상: `_fail_smoke()` 선언이 사라져 메인 스크립트가 파싱되지 않음
- 원인: 함수 본문에 로그를 추가하면서 함수 선언 행까지 교체함
- 복구: 함수 선언을 복원하고 모든 실패 경로가 `SMOKE_FAIL`을 출력하도록 유지했다.
- 상태: 해결

## 페이즈 3 — 월드·퀘스트

신규 오류 없음. Python 52개 테스트, Godot 퀘스트 스모크, Windows 내보내기와 내보낸 실행 파일 기동이 모두 통과했다.

## 페이즈 4 — 전투·적 AI

### P4-E001 · 신규 전역 클래스 추가 직후 첫 헤드리스 스모크 타임아웃

- 발생 단계: 스모크
- 증상: 신규 `BanditController` 추가 직후 첫 실행이 로그 없이 60초 제한에 도달
- 원인: 확정하지 못함. 같은 소스를 Godot 에디터 스캔으로 불러온 뒤 직접 실행과 자동 스모크가 모두 3초 안에 통과했다.
- 복구: verbose 에디터 로드로 전체 리소스 파싱을 확인하고 재실행했다.
- 상태: 해결

### P4-E002 · 병렬 검사 중 Windows 내보내기 임시 파일 잠금

- 발생 단계: 빌드
- 증상: `JOSEON_OUTLAW.tmp`를 읽기-쓰기 모드로 열 수 없어 내보내기 실패
- 원인: Godot 스모크와 내보내기를 같은 프로젝트에서 동시에 실행해 내보내기 캐시 접근이 겹침
- 복구: Windows 내보내기를 단독 재실행해 109,185,456바이트 실행 파일 생성과 기동을 확인했다. 이후 Godot 관련 검사는 직렬 실행한다.
- 상태: 해결

## 페이즈 5 — 전체 완주

신규 오류 없음. 고정 대사만으로 의뢰 수락, 도적 처치, 장부 획득, 지름길 귀환, 제출·보상·엔딩과 사망 후 체크포인트 부활을 자동 완주했다.

## 페이즈 6 — AI 대화

### P6-E001 · FastAPI 실행 의존성 누락

- 발생 단계: 환경 확인
- 증상: `import fastapi`가 `ModuleNotFoundError`로 종료
- 원인: 설계·검증 모듈만 있었고 실제 API 런타임 의존성을 설치·고정하지 않음
- 복구: `requirements.txt`에 FastAPI·Uvicorn 범위를 고정하고 현재 환경에 설치했다.
- 상태: 해결

### P6-E002 · 진행 중 HTTP 요청 취소 후 새 응답 유실

- 발생 단계: 실화면 AI 통합 스모크
- 증상: 서버가 실행 중인데 `--require-ai` 스모크가 캐시 응답을 받지 못함
- 원인: 상태별 사전 요청을 `cancel_request()`한 직후 같은 `HTTPRequest`를 재사용해 취소 완료 콜백이 새 요청 상태를 비움
- 복구: 캐시 초기화 시 기존 `HTTPRequest`의 시그널을 끊고 노드를 폐기한 뒤 새 요청 노드를 만든다. 이후 FastAPI→Godot 실 HTTP 스모크와 렌더 캡처가 통과했다.
- 상태: 해결

## 페이즈 7 — 완성·배포

### P7-E001 · 헤드리스 종료 시 절차 생성 오디오 객체 누수 경고

- 발생 단계: 스모크
- 증상: 성공 종료 뒤 `AudioStreamWAV`, `AudioStreamPlaybackWAV` 2개 누수 경고
- 원인: 오디오 출력이 없는 헤드리스 런타임에서도 재생 객체를 만들고 곧바로 프로세스를 종료함
- 복구: 스트림은 항상 생성해 계약을 검사하되 실제 재생은 화면 런타임에서만 시작한다. 헤드리스 종료 경고가 사라지고 GUI 렌더 실행에서는 배경음 재생을 확인했다.
- 상태: 해결

### P7-E002 · 릴리스 실행 파일에서 정적 메모리 계측값이 0

- 발생 단계: Windows 릴리스 기동
- 증상: 에디터·표준 런타임은 약 50.6MiB를 보고했지만 내보낸 릴리스는 정적 메모리 모니터를 0으로 반환해 스모크가 실패
- 원인: 릴리스 템플릿에서 해당 런타임 메모리 계측값을 제공하지 않음
- 복구: 메트릭 필드 존재와 로그 경로를 검증하고, 값 0은 “계측 불가”로 허용했다. 표준 런타임에서 FPS 124~145·정적 메모리 50.6MiB를 측정했고 릴리스 실행 파일도 전체 완주했다.
- 상태: 해결

### P7-E003 · 첫 Linux CI에서 Godot 초기화와 실행 파일 경로 실패

- 발생 단계: GitHub Actions
- 증상: 첫 실행은 프로젝트 최초 import 중 60초 제한에 걸렸고, 다음 실행은 AI 통합 도구가 Windows 로컬 Godot 경로를 사용해 실패
- 원인: CI의 빈 import 캐시를 고려하지 않은 제한과 `GODOT_BIN` 환경 변수를 무시한 통합 도구
- 복구: CI에서 프로젝트 import 단계를 먼저 수행하고 스모크 제한을 180초로 늘렸다. AI 통합 도구도 `GODOT_BIN`을 사용하게 변경했다. Linux Godot·FastAPI·10회 완주·Windows 내보내기·아티팩트 업로드가 1분 43초에 통과했다.
- 상태: 해결

## 비주얼 업그레이드

### VU-E001 · 신규 TTF 첫 실행에서 리소스 로더 미등록

- 발생 단계: 실게임 렌더 캡처
- 증상: 게임은 대체 서체로 실행됐지만 두 TTF에 `No loader found for resource` 오류가 발생
- 원인: 신규 폰트를 Godot 에디터 import 전에 런타임 씬에서 바로 불러옴
- 복구: `godot --headless --editor --path game --quit`으로 import를 선행한 뒤 같은 GUI 스모크를 재실행했다. 오류 없이 두 서체와 UI가 렌더되고 페이즈 7 전체 스모크가 통과했다.
- 상태: 해결

## 현실적 오픈소스 비주얼

### RV-E001 · Linux CI에서 Git LFS 자산 미다운로드

- 발생 단계: Pull Request GitHub Actions
- 증상: Python 검사는 통과했지만 Godot가 HDRI와 PBR 텍스처를 불러오지 못해 메인 씬 로딩 실패
- 원인: `actions/checkout`이 Git LFS 포인터만 받고 실제 바이너리를 내려받지 않음
- 복구: 빌드와 Pages 체크아웃에 `lfs: true`를 설정하고 Godot import가 끝날 때까지 기다리는 `--quit` 방식으로 변경했다.
- 상태: 해결
